AppCheck (Vercel version)
Layout: api/index.py is one Python serverless function that handles every route (vercel.json rewrites all paths to it). lib/ holds config (all env vars), db (Postgres via DATABASE_URL, SQLite fallback for local dev), scanner (passive checks with private-address blocking), verify (meta tag or /.well-known/appcheck-verify.txt), ratelimit (DB-backed, per IP and per email), billing (Stripe Checkout + webhook signature check via REST, no SDK), crm (Resend Audience contact sync), nudges (day-2/day-5 follow-up emails with one-click unsubscribe), mailer (Resend or Postmark, or log), views (HTML).
Routes: / , /pricing , POST /start , /site/<private key> (+ /verify /scan /checkout /monitor), /report/<token>, POST /api/stripe/webhook, GET /api/cron/weekly (Bearer CRON_SECRET; Vercel Cron, Mondays 14:00 UTC), /api/health, robots.txt, sitemap.xml.
Local dev: python3 dev_server.py (port 3000). End-to-end test with real local Postgres and mocked Stripe/Resend: tests/run_e2e.sh. Env vars: see .env.example. The old SQLite MVP is in legacy/.
